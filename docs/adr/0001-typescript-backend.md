# Rewrite the backend from Go to TypeScript (Node 22 + Hono)

The backend was rewritten in-place from Go (chi) to TypeScript on Node 22 with Hono. Motivation: keep the number of languages in the project low and deepen TypeScript specialization. The HTTP contract is preserved exactly (routes, status codes, middleware semantics), so the frontend and Caddy needed no changes. Two deliberate deviations from the Go behaviour: MusicBrainz releases with an empty `artist-credit` are skipped instead of crashing the process, and the 30s request timeout covers only `/api/search` — `/api/import/detect` is bounded by the album-detector client's 300s timeout instead, since video detection can legitimately take minutes. The Python album-detector service is deliberately out of scope — OCR/CV stays in Python behind its HTTP boundary.

`/api/import/detect` buffers the upload in memory before forwarding it to album-detector, exactly as the Go version did. A streaming forward (`duplex: 'half'` piping the incoming body into the upstream fetch) was attempted and reverted: under @hono/node-server the forwarded body stream stalls and the upstream request never completes, surfacing as a 30s timeout and 503. Buffering is safe here because request size is capped at 30MB.
